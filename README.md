# Weave · 织

> 一个属于你自己的 AI 个人助手：视觉流畅的对话体验 + 上千工具的后端能力平台 + 真浏览器自动化 + 本地工作区与沙箱。
> 目标：像 Claude Code 一样舒适，但面向**日常生活**而不是编码——订票、旅游规划、秋招网申、信息整理，一个知根知底的助手高效解决。

## 为什么存在

现有工具的两个缺口：

1. **CLI 类助手（Claude Code 等）只面向编码**：终端交互、视觉表现弱、工具生态围绕开发，无法优雅地"帮我填 300 个秋招网申"。
2. **聊天类助手（网页版 ChatGPT 等）没有手和脚**：不能操作本地文件、不能控制真实浏览器、工具数量一多就失控。

Weave 的答案是一套经过验证的组合：

- **瀑布流对话前端**：轮次（Turn）= N ×（过程 + 回答），过程默认折叠为摘要行，答案逐字揭示；运行中可补充、可排队、可分支、可压缩——对话本身就是生产力界面。
- **超大规模工具平台**：后端按"域 → 目录 → 工具"组织成百上千个工具，模型通过**发现原语**（目录树 / 搜索 / 按需读 schema）定位工具，而不是把几百个 schema 塞满上下文。工具可以对应工厂的一道工序，也可以对应日常生活的一件小事。
- **真浏览器自动化（WebBridge）**：借出一个真实 Chrome 窗口，模型看页面状态、执行动作、随时被人接管——网申、抢票、批量填表的终极形态。
- **本地工作区 + Python 沙箱**：文件读写有围栏、有检查点可回滚；数据处理交给沙箱里的 Python，安全可审计。

## 设计信条

1. **减少视觉移动，不主动打破专注**——一切动画服务于注意力锚定，审批淡化收拢、补充 chip 化、分支切换原地完成。
2. **历史是一棵倒着的树**——对话不丢失：分支变体、压缩线、工具调用细节全部持久化，任意位置可回到、可分叉。
3. **工具是生活用品**——一个工具 = 一件结构化的小事（查快递 / 记账 / 填表 / 订票）。组织方式与电脑目录一致：域是房间，目录是抽屉，工具是物品。
4. **先发散后收敛的发现**——模型面对 1000+ 工具时的元认知流程：意图 → 目录统计 → 读 schema → 澄清 → 调用，禁止凭名字猜参数。
5. **危险动作必有审批**——写操作、支付、提交表单前，一条优雅的审批条出现在对话框上方，整条可点、淡化退场。
6. **本地优先，数据自持**——SQLite/本地文件系统是一等公民；云端只是可选增强。

## 与 Claude Code 的对照

| | Claude Code | Weave |
|---|---|---|
| 面向 | 编码任务 | 日常生活 / 工作琐事 |
| 交互 | 终端文本 | 瀑布流可视化对话（自研前端） |
| 浏览器 | 无 | 真 Chrome 窗口自动化 + 人工接管 |
| 工具规模 | 内建 ~20 | 平台化设计，1000+ 可扩展至上万 |
| 工作区 | 代码仓库 | 个人文件空间 + 检查点回滚 |
| 沙箱 | shell | Python（数据处理/文档生成） |

## 技术选型（推荐）

- **后端**：Java 21 + Spring Boot 3 + WebFlux（SSE 天然对口）+ Spring Data JDBC + SQLite/H2 起步
- **前端**：Vite + React 18 + TypeScript + Tailwind + zustand + react-virtuoso
- **浏览器自动化**：Node.js 守护进程（CDP）或 Java + Playwright——见 docs/05 权衡
- **打包**：exe = 后端自包含 + 前端静态资源 + Inno Setup
