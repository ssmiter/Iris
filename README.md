# Iris

> 一个属于你自己的 AI 个人助手：瀑布流对话前端 + 原生 Agentic Java 后端 + 可组合的能力网络 + 真浏览器自动化 + 本地工作区。
> 目标：像 Claude Code 一样可靠好用，但面向**日常生活**而不是编码——订票、出行规划、秋招网申、记账、信息整理。
>
> 中文命名故事：Iris 是希腊神话中的彩虹女神、众神与人间的信使（"虹使"）。详见 [docs/10](docs/10-naming-and-identity.md)。

## 为什么存在

桌面助手早已不是"没有手和脚"的时代了——官方产品们已经能操作浏览器、读写文件、连接各种服务。但真正的缺口从来不在"能不能做"，而在：

1. **它们是通用的，而你的生活不是。** 官方助手面向所有人的平均水平设计；而真实生活充满了非规则化的需求——"帮我把这 300 家风马牛不相及的网申按我的优先级填掉"、"按我家的规矩记账"、"用我习惯的方式整理这一堆杂乱文件"。这些需求没有现成按钮，只能从你的生活中抽象出来。
2. **它们的能力是封闭的，而你的问题需要组合。** 官方工具箱给什么用什么；但真正解决生活问题，往往需要把客观原语（读文件、观察页面、计算、写入、验证）按你的情境自由组合成新的能力——组合权必须在你和 Agent 手里，而不是在产品经理的路线图里。

Iris 的回答：**自己造一个扎根本地的助手**。它只读你的文件、只操作你的工作区、只记住你的偏好；它的能力不是一堆按钮，而是一棵可以由你持续生长的能力树。

## 真正要解决的问题

把话说透：对话前端、Agentic 内核、能力目录、工作区、Python 执行、WebBridge——这些**都是手段，不是目标**。参考已有的优秀工作（Claude Code 的内核、企业后端的工具生命周期、WonWork 的交互与 daemon）能高效地把这些基础能力做到它们的水平，但基础能力齐备之后，真正难、也真正重要的是：

> **怎么从模糊、非规则、强情境的日常需要中，抽象出组织良好的能力。**

工厂有固定流程，所以 MES 能把每道工序做成工具；日常生活也有流程，但它们模糊、私人、随时变化。按流程、按领域、还是按思路去设计和组织工具？能力目录只是架构——就像 Windows 的文件夹，目录结构只是管理形式，**文件夹里的内容才是真正重要的**。工具的元数据（目录路径、一句话描述、schema）是为了让 Agent 分层发现、高效自取；但工具本身执行什么，对 Agent 必须是**客观的**：

> 加减乘除之所以能组成复杂计算，是因为它们拥有清晰语义和可验证结果。生活工具要接近这种"求解器土壤"，至少需要六类原语——**观察**（读文件、页面状态、搜索）、**变换**（计算、解析、文档处理）、**行动**（写文件、提交、浏览器操作）、**验证**（重读、比对、查业务编号）、**协作**（澄清、审批、接管）、**恢复**（检查点、幂等查询、补偿）。

"工具多"不等于原语完备。真正的判断是：Agent 遇到一个新任务时，能否观察缺口、构造动作、得到客观反馈，并在失败后定位——是工具缺失、契约不好，还是策略错误。

所以 Iris 的能力网络分两层，共享同一套发现与运行底座：

- **系统原语能力**：客观小动作，语义清晰、结果可验证、组合时不夹带领域假设；
- **生活领域能力**：围绕求职、出行、财务、整理等真实任务抽象出的能力，必须说明适用情境、前置条件、证据和失败出口。

前期把求解器做可靠（发现、组合、上下文、恢复）；后期的主要研发对象是"一个具体生活能力怎样抽象才真正有效"——而不是无限扩建通用 Loop。（详见 [docs/02 §5.3](docs/02-architecture-overview.md)、[docs/01 §2](docs/01-vision-and-principles.md)）

## 路径：Agentic 探索，Pipeline 沉淀

实现上述目标的核心机制，是同一运行内核上两种可互相转化的求解形态：

- **Agentic Run**：面对路径未知的任务，观察环境、发现原语、试错修正、直到求解。成本高，但什么都能试。自然语言需求默认从这里进入。
- **Pipeline Run**：重放已经被理解的成功过程——固定输入输出、步骤、检查点和证据。便宜稳定，但遇到新情境会失配。

Agentic 探索出的成功轨迹，经识别前置条件、抽离偶然数据、标注审批点、人工发布版本后，沉淀为 Pipeline；Pipeline 遇到前置条件失效，受控回退给 Agentic 修复。成功一次的轨迹**不会**自动固化——靠偶然页面状态走通的路径、包含未声明人工判断的路径、只能靠"模型说成功"证明的路径，都不能发布。（详见 [docs/02 §5](docs/02-architecture-overview.md)）

## 工具的隐喻：从工厂到生活

大规模工具平台的灵感来自制造业 MES：一个工厂有几百上千个"工序"，每个工序是一个结构化的操作。把它平移到个人生活：

| 工厂概念 | 个人生活对应 |
|---|---|
| 工序（查/改/录） | 一件小事：查快递、记账、订票、填表 |
| 车间 / 产线 | 生活域：财务、出行、求职、健康、家庭 |
| 工艺路径 | 工具的目录组织：/finance/express/query |
| 作业指导书 | 工具 description + 参数 schema |
| 生产审批 | 写操作审批条（影响陈述 + 勾叉） |
| 批次追溯 | 工作区检查点 + 对话分支多叉树 |

**工具是生活用品**：组织方式与电脑目录一致——域是房间，目录是抽屉，工具是物品。关键洞察：**工具数量会膨胀，但人和模型的当前注意力都不会膨胀**。所以模型面对上千工具时走发现原语（目录统计 → 进入分支 → 按需读 schema → 澄清 → 调用），不凭名字猜参数，schema 也不会永久驻留上下文。

## 设计信条

1. **历史是一棵倒着的树**——对话不丢失：分支变体、压缩边界、工具调用结构全部持久化；任何优化只能改变"当前视野"，不能丢弃信息。在哪个位置分叉，就用那个位置该用的上下文。
2. **发现优于塞满**——schema 不预装进上下文；先发散（目录/搜索）后收敛（按需读取），禁止凭名字猜参数。
3. **危险动作必有审批**——写操作、支付、提交表单前挂起等待，用一句人话说清影响；批准绑定不可变的操作快照，不是会漂移的工具名。
4. **路径围栏**——文件工具只允许操作工作区根目录内，越界一律拒绝（fail-close）。
5. **减少视觉移动，不主动打破专注**——动画只为锚定注意力：过程折叠为摘要行，答案逐字揭示，审批条原地淡化收拢，补充消息 chip 化。
6. **本地优先，数据自持**——SQLite 与本地文件是一等公民；不需要 24 小时常驻，重启后未闭合的事实可以恢复。

## 与 Claude Code 的对照

| | Claude Code | Iris |
|---|---|---|
| 面向 | 编码任务 | 日常生活 / 工作琐事 |
| 交互 | 终端文本 | 瀑布流可视化对话（自研前端） |
| 浏览器 | 无 | 真 Chrome 窗口自动化 + 人工接管 |
| 工具规模 | 内建 ~20 | 平台化能力树，可生长至上万 |
| 工作区 | 代码仓库 | 个人文件空间 + 检查点回滚 |
| 执行环境 | shell | Python（数据处理/文档生成） |

Claude Code 是 Iris 内核能力的对标：Agentic 循环、工具与环境深度交互、长对话稳定性——这些要做到它的水平。但编码不是 Iris 的第一目标；它要面对的还是非规则化的日常需求。

## 四个组成部分

- **瀑布流对话前端**（Vite + React + TS）：轮次 = N ×（过程 + 回答），过程默认折叠、答案逐字揭示；运行中可补充、可停止，历史可分支、可压缩。
- **Agentic 后端**（Java 21 + Spring Boot 3 + WebFlux + SQLite）：Loop 在后端——Turn / Run / Round 持久化状态机、模型协议装配、上下文预算与压缩、唯一 Tool Runtime（claim → prepare → approval → execute → verify），SSE 是唯一流式通道。
- **能力平台**：工具按"域 → 目录 → 工具"组织，**文件目录即能力树路径**；每个工具声明一句话描述、风险等级和参数 schema，经能力目录被模型发现，而不是被记住。
- **WebBridge 浏览器自动化**（规划中）：借出一个真实 Chrome 窗口（带你的登录态），模型看页面、做动作，你随时接管；录制一次示范，沉淀为可重放的工作流。

## 技术栈

- **后端**：Java 21 + Spring Boot 3（WebFlux）+ Spring Data JDBC + SQLite
- **前端**：Vite + React 18 + TypeScript + Tailwind CSS + zustand + react-virtuoso
- **浏览器自动化**：Node.js 守护进程（CDP / Playwright，见 [docs/05](docs/05-webbridge.md) 权衡）
- **打包**（后期）：后端自包含 jar + 内嵌前端 + Inno Setup exe

## 本地运行

```bash
# 后端 :5001（模型经 IRIS_MODEL_* 环境变量注入，密钥不入库）
cd backend && ./mvnw spring-boot:run

# 前端 :5173（/api 代理到 :5001）
cd frontend && npm install && npm run dev
```
