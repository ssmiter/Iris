## 1. 房间设计语言（通用骨架，不止能力房）

用户 2026-08-24 裁决：这套风格**沿用到设置页等所有房间**。因此蓝图语言先抽象为
通用骨架，能力房只是第一个完整承载者。共享组件落在 `components/room/`：

| 骨架件 | 职责 | 能力房中的形态 | 设置房中的形态（预留） |
|---|---|---|---|
| `RoomShell` | 全屏覆盖房（见下） | 全屏 | 同一壳 |
| `RoomTopBar` | ← 返回 · 房间名 · 居中搜索（⌘K）· 右侧动作 | 搜索能力 | 搜索设置项 |
| `RoomSide` | 左导航列 | 目录树 + 收藏 | 分栏菜单 |
| `RoomStage` | 内容列（max-w ~880px 居中，纵向节奏） | 目录舞台 | 设置分组 |
| `DetailLayer` | 右侧 370px 推入详情层（房间内浮层） | 能力详情 | 设置项详情（少用） |
| `NoticeBar` | 顶部「需要注意」聚合条，可点击下钻 | problems 聚合 | 配置异常聚合 |
| `ConfirmDialog` | 确认对话：人话后果陈述块，「算了」永远在场 | 删除/停用确认 | 同 |
| Toast 撤销 | sonner `action`（样式已配，业务零使用——本次接线） | 移动可撤销 | 同 |

**全屏裁决（2026-08-24，用户指示「可以激进一些做到和蓝图一致的水平，我们也要全屏」）**：
能力房从 37 §1 的「居中适度大窗」升级为**全屏覆盖**（蓝图同款：顶栏 52px + 左树 236px +
舞台，`overflow:hidden`，房间即应用）。该裁决**取代** 37 的「不要近全屏」——
当时怕比例失衡，蓝图证明了全屏 + 内容列收敛（max-w 880px）才是正解。
不变量保留：对话层**只遮不卸**（SSE/滚动/流式状态原位保留），Esc/← 返回等价回家；
设置房等后续房间沿用同一全屏壳。37 §1 其余部分（无滑入转场、淡入上限）仍然有效。

反馈纪律沿用 38：轻操作无声、实质操作就地反馈 + toast（可撤销）、不可逆才打断。
Esc 层栈全房间统一：浮层 → 详情 → 搜索 → 选择 → 房。

## 2. 能力房舞台：三种心境三种视图

38 的三种心境在舞台上的落地形态（对齐蓝图 §舞台）：

- **逛（根视图）**：域大卡片格（图标砖 + 目录名 + 一句话说明 + 计数 + 需要注意点）。
  **后端早已返回 `listing.directories`，前端从未消费**（全仓仅类型定义一处引用）——
  本次纯前端接线，零后端改动。
- **找（搜索）**：`/` 或 ⌘K 聚焦，**跨目录**过滤（现状只滤当前目录的 fuzzy），
  结果按路径分组平铺、匹配字符高亮、每行带路径；Esc/清空即回当前目录。
- **排障（聚合）**：`problems` 从底栏计数 Badge 升级为顶部 NoticeBar
  （左黄条 + 「N 个能力需要注意：xxx」+ 去看看 →），点击直达详情/问题清单。

目录视图结构：面包屑（可点）→ 目录头（title + description + 计数 + 目录菜单）
→ 子目录砖排（消费同一个 `directories`）→ 能力砖格 → 空态（一句话 + 下一步引导）。

## 3. 详情层（右侧推入，替代行内展开）

现状详情是内容区底部追加的行内块（`CapabilityExplorer.tsx` 尾部），改为
**房间内右侧 370px 推入层**（transform 推入，时长压进 `fold` token，motion-reduce 降级）：

```
┌ 图标砖 · 名称 · 路径面包屑（可点） · ✕ ┐
├ 状态行（正常即安静；异常出黄点+原因）  ├
├ 主开关（仅可启停者出现，见下）         ├
├ 修复盒（该能力关联 problem 时）        ├
├ 说明                                  ├
├ 档案（来源 / 版本 / 权限 / 风险 / 最近）├
├ 底部动作：移动到… · 删除               ├
```

- **主开关诚实原则**：启停只对 DB 真相有意义（skill / MCP / memory / schedule，
  后端已有 enabled PATCH）；内核工具与文件真相能力没有启停概念（只有遮蔽与
  可用性探针），**不显示开关**——不造假控件。
- 路径面包屑点击 = 跳到对应目录（详情层随之切换到该目录上下文）。

## 4. 编排操作

- **移动到树选浮层**：详情层底部「移动到…」弹出目录树选择浮层（只列合法落点：
  文件真相对象 → 拓展根目录；DB/内核对象不出现此动作）。复用既有
  `POST /capability-admin/files/move`，成功后 **toast 带「撤销」**（撤销 = 再 move
  回去，文件操作天然可逆）。剪切/粘贴肌肉记忆保留，浮层是补充不是替换。
- **删除确认带后果陈述**：沿用既有确认 Modal，补一块后果区
  （蓝图 `.mcon` 手法：「正在使用它的任务会失败；文件仍可从 git 恢复」）。
- **右键菜单保留**：现状分档（文件真相 / DB 真相 / 内核）不动，仅把「移动到…」
  加进文件真相档（与剪切并列，指向同一浮层）。

## 5. 诚实边界（真相树约束：不做 / 缓做）

蓝图的目录编排动作在 Iris 受「文件目录即能力树路径」铁律约束，逐条裁决：

- **新建 / 改名 / 删除目录：本期不做**。内核目录由 Java 包名派生
  （`DomainCatalog.inferPath`，第一原则不可动）；拓展根目录元数据在
  `_directory.yml`，理论上可由 files API 扩 mkdir/rmdir——缓做，待真实诉求。
  树右键维持现状（粘贴 / 复制路径）。
- **目录级停用：缓做**。后端无任何目录启停概念（catalog 包 grep 零命中），
  内核工具本就不可停用。与 docs/35 §5 规则化权限（allow/ask/deny）合并评估，
  届时目录可能作为策略作用域复活。
- **最近使用：缓做**。无 recency 数据源（后端仅 pipeline recentRuns）。
  可从 tool execution 记录派生 lastUsed——留作后端小增量，本期根视图
  只上域卡片，不做占位近期区。
- **修复日志流：缓做**。修复盒第一期 = problem 描述 + 「打开文件」定位动作；
  蓝图的重连/日志回放属于 MCP 场景，待 MCP 控制台整合时再评。
- **蓝图的自由新建目录内联输入、整目录停用确认**：随上两条一并缓做，
  UI 不留死控件（与「前端不引死 UI」纪律一致）。

## 6. 结构重排（CapabilityExplorer 巨石拆分）

`CapabilityExplorer.tsx`（1733 行）把加载/缓存/选择/剪贴板/键盘/框选/菜单/
详情揉在一个组件里，本次顺势拆分（纯移动，不改行为语义）：

```
components/capabilities/room/
  CapabilityExplorer.tsx   壳：数据加载、键盘层栈、选择/剪贴板状态（目标 <700 行）
  StageView.tsx            面包屑 + 目录头 + NoticeBar + 域卡片 + 子目录砖 + 砖格
  DetailLayer.tsx          右推详情层（吸收 CapabilityDetailPanel 内容）
  MoveToPopover.tsx        移动到树选浮层
  CapabilitySearch.ts      跨目录过滤 + 高亮工具（纯函数）
components/room/           通用房间骨架（§1 表中的可复用件）
```

`capabilityCenterCache` 模块缓存与 generation 探针协议**不动**（37 §2.5 已验收）。

## 7. 按压反馈（全前端统一，用户 2026-08-24 指定对齐 WonWork）

WonWork 的点击反馈是一套极简但处处在场的体系（`wf-press`），迁移为 Iris 全局工具类：

- **基线**：`.press { transition: transform .12s } .press:active { transform: scale(.98) }`——
  所有按钮、chip、砖、树节点、菜单项都挂；按压即回应，是「丝滑有反馈」的地板。
- **卡片/行级例外**：大面积元素不做几何缩放（缩放在圆角边缘露出下层底色，
  WonWork 2026-08-11 踩过的色差边），改 `filter: brightness(.965)`——
  等价手感、不露底、不破坏圆角阴影所在层。
- **开关类**：`:active { transform: scale(.92) }`（更小幅度，小控件不至于按飞）。
- **危险二次确认**：`.armed` 态（第一次点击武装成红底，第二次才执行）用于
  行内小删除按钮；大确认仍走 ConfirmDialog。
- 时长锁死 .12s（instant–fast 之间），不进 token 表（它不是转场是生理反馈）；
  motion-reduce 下一律关闭。

## 8. 字体统一（全前端，用户 2026-08-24 指定）

现状 Iris 是纯系统字体栈（macOS 字体打头），Windows 上落到 Segoe UI + 雅黑，
与蓝图/WonWork 的观感差距主要在字体。统一为蓝图同款栈：

- **sans**：Manrope（西文/数字，几何感、字距干净）+ Noto Sans SC（中文）+
  系统栈兜底。 WonWork 走 Google Fonts CDN；Iris 是本地 exe 产品，**必须离线**，
  走 `@fontsource` 打包进构建产物（fontsource 按 unicode-range 分包，
  浏览器只下载用到的区段，可接受）。docs/37 §4「前端不引新依赖」指运行时
  组件库，字体资产属设计基座，用户已明确指定，不在其列。
- **mono**：沿用 Cascadia Code 栈（路径、计数、日志），不动。
- 加载纪律：`font-display: swap`，首屏不阻塞；字重只引 400/500/700
  （蓝图 800 的标题重量在 Iris 用 650–700 克制区间替代）。
- caption ≥12px 下限决议不变（Windows 灰度渲染），与字体更换无关。

## 9. 视觉打磨清单（边实现边打磨，不一次写死）

- 砖格节奏：现状 `minmax(10rem,1fr)` 偏宽，对齐蓝图「手机桌面节奏」收窄试
  （~6.5–8rem），宽屏下按手感定；砖 hover 只升图标（scale 1.05），不抬砖。
- 树节点选中态：当前支链左侧 3px accent 圆角条（蓝图 `tnode.on::before` 手法），
  替代或叠加现有底色，实现时对比定稿。
- 入场：域卡片/砖格出生用既有 `node-enter` 单次播，允许 ≤16ms 逐项错落；
  就位即静止（38 安静第一）。
- 详情层推入 260–360ms 自然缓动；遮罩不加（房间内浮层，不阻断舞台）。

## 10. 验收标准

1. 根视图渲染域大卡片（消费 `directories`），可点击进入对应目录；
   目录视图有面包屑、目录头（title/description/计数）、子目录砖；
2. 搜索跨目录、按路径分组、匹配高亮；Esc/清空回当前目录；
3. problems > 0 时 NoticeBar 出现在舞台顶部，点击下钻到问题能力详情；
4. 详情改为右侧 370px 推入层：状态行 / 主开关（仅 DB 真相）/ 说明 / 档案 /
   底部动作齐全；Esc、✕、点外三条退出路径等价；
5. 「移动到…」树选浮层可用（文件真相对象），成功后 toast 可撤销；
   删除确认带人话后果陈述；
6. 通用骨架件落 `components/room/`，能力房引用之（设置房接入是后续独立任务）；
7. 全部动画 ≤fold token（360ms）且单次；按压反馈 .12s 全控件在场；
   motion-reduce 全降级；无轮询；token 纪律零违规；
   `CapabilityExplorer.tsx` 降至 700 行以下；
8. 全前端字体切到 Manrope + Noto Sans SC（fontsource 离线打包，
   `font-display: swap`），系统栈兜底；mono 栈不变。
