# 混合语义召回

Iris 中的“召回”不是替 Agent 作判断，而是从大规模对象集合中提供少量、可解释的候选。它首先服务能力目录，随后可以复用于记忆、Artifact、任务状态和其他语义对象；对象自己的状态机与权限仍由各自领域负责。

## 1. 不变量

1. **先过滤，后相似**：作用域、状态、可见性、类型与生命周期条件先决定合法候选集，相似度不能越过围栏。
2. **精确锚点不被稀释**：名称、路径、编号、短语和关键词命中是高精度证据；向量用于补足同义、口语、跨语言和不同表述。
3. **召回不是事实**：词法分数和语义分数只说明“值得让 Agent 看”，不能直接写入记忆、激活工具或改变外部状态。
4. **语义通道可失效**：模型缺失、加载失败或编码超时时，系统退化为关键词检索，主 Agent 不因此不可用。
5. **证据可观察**：候选保留 lexical、semantic、combined、exactAnchor、strategy 与模型 identity，便于调优和解释。

## 2. 一个底座，多种计划

检索执行器接受已经通过领域过滤的候选与词法证据，再按场景选择计划：

- 并行融合：关键词与向量同时召回，适合中等规模且需要发现语义近邻的目录；
- 词法粗召回、语义重排：适合候选极大且关键词通常存在的场景；
- 语义粗召回、精确确认：适合口语化输入，但最终必须核对编号、名称或关键约束的场景；
- 纯词法降级：模型未配置、超时或数据不适合向量化时使用。

首版采用并行融合，但接口不把计划固定为能力目录专属实现。精确锚点获得最低排名保障；非精确结果只有词法命中或语义超过阈值时才进入结果集。权重与阈值是策略参数，不是对象事实。

## 3. 向量运行时

本地 ONNX 编码器按需加载，不随每轮对话重复创建。文本先做稳定的 Unicode/空白归一化，再用 WordPiece 编码；模型输出经 attention-mask mean pooling 与 L2 归一化，余弦相似度退化为点积。

持久缓存键必须包含：

```text
model identity + normalization version + normalized content hash
```

仅按原始文本缓存会在模型、词表或归一化逻辑升级后静默复用错误向量。向量以紧凑二进制保存到 SQLite；进程内只维持有界热缓存。模型文件和词表是本地运行环境资源，不进入仓库，也不进入对话上下文。

## 4. 与 Agentic 内核的关系

能力搜索仍返回少量候选路径，Agent 必须 `read_capability` 读取精确定义，再由 ToolRuntime 核对 manifest hash 后执行。语义召回减少的是“找到哪一页”的成本，不会绕过发现、精确绑定、审批和执行闭环。

记忆接入时也遵循相同边界：结构化状态和作用域先过滤，混合召回给出候选，Agent 或固定 Pipeline 判断是否真正相关；读取不会提升记忆权重，只有明确的使用事实才能更新生命周期，避免自我强化回路。

## 5. 当前落点

- 能力目录的普通文本查询接入混合召回；正则查询保持确定性的纯词法语义。
- 默认不配置编码模型，因此现有安装零成本退化到原有关键词结果。
- 配置本地模型与词表后，候选向量持久缓存，响应返回分项证据。
- 记忆、Artifact 等域只复用检索底座，不在本阶段预设它们的完整状态字段。
