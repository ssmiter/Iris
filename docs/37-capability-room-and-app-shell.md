# 37 · 能力管理大屏与应用壳房间模型（设计稿）

> 状态：**设计稿 v2**。素材：wonwork-能力页蓝图-v12、应用壳原型
> （对话侧边栏与设置）、chatgpt 设置页/对话页照片、用户 2026-08-20 指示
> （Iris 自成风格但体验一致；信息更省；能力管理大屏 + 右键菜单 +
> 剪切/粘贴/重命名/点开编辑，Windows 资源管理器手感；字体清晰度对齐 ChatGPT；
> **覆盖窗口适度收敛不全屏**；**索引缓存 + 手动全量刷新，不实时传全量元数据**）。
> v2 增量：§1 尺寸收敛、§2.1 签名交互、§2.5 索引缓存协议（据 API 现状探索）。
> 实现排第三波，前置：第二波（干净度 + M17）已落地并推送。

## 1. 空间模型：覆盖式房间（适度大窗，非全屏）

用户 2026-08-20 定稿：**覆盖层而非替换层**——对话页始终在下层保持
挂载与可见，能力层居中覆盖，点旁边空白即返回，无切换认知负担；
不用滑入、不用转场大动画。同日二次裁决：**不要近全屏**，适度收敛——
全屏覆盖在显示器上比例失衡、反而难看。

- 能力中心从 Modal 升级为**居中覆盖大窗**：`position:fixed` 居中，
  尺寸 `min(1120px, 92vw) × min(760px, 82vh)`——比 ChatGPT 设置页
  更大更清晰，但四周始终留出一圈看得见的对话边缘（桌面下至少
  60-80px 量级），圆角 14-18px + 大软阴影（`--pop` 级）。
- 下层对话**只加一层极淡的压暗**（canvas 40-50% 透明遮罩，随能力层
  一次性淡入），不缩放不模糊——用户看得见"对话还在那儿"。
- **点遮罩/边缘空白 = 返回**；Esc = 返回；头部"← 返回" = 返回。
  三条回家路径等价，零学习成本。窗口适度收敛后边缘更宽，
  "点空白回家"的目标区域反而更大。
- 动效上限：覆盖层与遮罩各一次 opacity 淡入（≤duration-fast），
  无位移、无缩放、无滑入。
- 对话层只遮罩不卸载（SSE/滚动位置/流式状态全部原位保留）。
- 实现走 viewStateStore 视图态（不引入前端路由）；同一覆盖机制日后
  可承载设置房。

## 2. 能力房内部：Explorer 式管理

### 2.1 布局（比 chatgpt 设置页更大更清晰）

```
┌ sticky 头：← 返回 · 能力 · [搜索] ─────────────┐
├────────────┬──────────────────────────────────┤
│ 目录树列    │ 内容区（当前目录）                 │
│ （可折叠）   │ 大图标/列表两种视图               │
│            │ 右键菜单 / 多选 / 拖放            │
├────────────┴──────────────────────────────────┤
│ 状态行：N 项 · 选中 M 项 · 目录统计             │
└────────────────────────────────────────────────┘
```

- 字号规格对齐资源管理器可读性：内容区对象名 14px/500、辅助行 12.5px、
  组标题 12px letterspacing muted（原型 `.side-g`/`.group-t` 同款）。
- **信息减重**：卡片不再堆徽标——kind 由图标砖表达、风险只在详情与
  destructive/elevated 时出边缘色、来源收成详情一行；列表态每行 =
  图标砖 + 名称 + 一句话 + 状态点文字。
- 目录统计沿用 `_directory.yml` 三口径，放状态行而非每目录一堆数字。

**签名交互（Iris 的"独到简洁"落在四处肌肉记忆上）**：

1. **单链树**：树列默认只展开当前路径一条支链，点另一支自动收起旁支——
   树列永远干净，不会滚成多叉爆炸；Alt+点击可临时保持多支。
2. **搜索即过滤**：`/` 或 Ctrl+F 聚焦搜索框后，输入直接在内容区平铺过滤
   （名称/路径模糊匹配），结果项带路径面包屑；没有独立"搜索结果页"，
   Esc 或清空即回当前目录。
3. **键盘全程可达**：↑↓ 移动、Enter 打开详情/进入目录、Backspace 回上级、
   菜单键/Shift+F10 开右键菜单、Esc 逐层退出（菜单→选择→房）。
4. **框选与多选**：空白处拖拽框选 + Ctrl/Shift 点选；选中态只在图标砖
   外圈一道 1.5px 强调环（不打底色块，保持纸面干净）；状态行报
   "N 项 · 选中 M 项"。

### 2.2 右键菜单（按真相源分档，docs/36 方向落地）

新建 `ui/ContextMenu.tsx`（自绘轻量：复用 PermissionModeSelect 的菜单语言，
不引新依赖；键盘可达、Esc 关闭、点外关闭、暗色胶囊）。菜单内容按对象
真相源分档：

| 真相源 | 菜单项 | 语义 |
|---|---|---|
| 文件真相（process/template/skill/knowledge） | 打开编辑 / 剪切 / 复制 / 粘贴 / 重命名 / 删除 / 在文件夹中显示 / 复制路径 | 剪切粘贴 = 真实移动文件；重命名 = 真实改文件名（manifest 同步）；删除先确认 Modal |
| DB 真相（kernel_skill/mcp 手工/schedule） | 打开编辑 / 重命名（语义允许处）/ 删除（确认）/ 复制路径 | 编辑进现有编辑器 |
| 内核工具 | 详情 / 复制调用名 / 复制路径 | 包名即路径不可动，菜单诚实收敛 |

- **多选**：Ctrl/Shift 点选 + 空白处框选（资源管理器肌肉记忆）；
  多选菜单只剩可批量执行的动作（剪切/删除）。
- **拖放**：对象拖到目录树节点 = 移动（与剪切粘贴同一后端动作）；
  只允许文件真相对象、只提示合法落点。
- 剪切板语义照 Windows：剪切后源项半透明待粘贴；跨目录粘贴 = 移动；
  同名冲突拒绝并提示；复制粘贴 = 副本（"xxx 副本"后缀）。

### 2.3 后端文件操作写接口（新增）

挂在 `/api/v1/capability-admin/files`（管理面，与模型原语完全分离）：

- `POST /move`（source→target 目录）、`POST /rename`、`POST /copy`、
  `POST /delete`，全部：
  - **拓展根围栏 fail-close**：源与目标都必须解析在已登记拓展根内，
    越界一律拒绝（与不变量 4 同构）；
  - 内核目录/DB 真相路径直接 422；
  - 操作成功后触发该根热重扫（复用现有重扫管线），目录树投影自动跟随；
  - 冲突不覆盖，返回结构化 409。
- 操作主体是**用户本人在界面上直接操作**，不经模型——不破"写操作必
  审批"（那是对模型工具的不变量）；删除仍走前端确认 Modal。
- 管理页第一次有写能力：审计留痕（log + 操作返回投影），不做回收站
  （克制：删除有确认，文件仍在 git/文件系统可恢复时不造第二机制）。

### 2.4 策展层（真相树之上的自由组合）

"可拖动自由组合"的组织欲由策展层承接，不动真相路径：

- 目录树顶部一个「收藏」区：任意能力可钉入（右键菜单"钉到收藏"），
  收藏区内自由排序（拖放仅改展示顺序）；
- 持久化 SQLite 单表（capability_pin：path + ordinal），重启保留；
- **不做**自定义嵌套文件夹（第一期克制：收藏平铺已覆盖 80% 诉求，
  嵌套分组留待实际手感再评）。

### 2.5 索引缓存与刷新协议（为目录上量级设计）

用户 2026-08-20 指示：前端持有索引缓存 + 手动全量刷新按钮；不实时、
不每次传全量元数据（描述全文、参数 schema 上量级后传输与渲染都是浪费）。
现状探索结论：**index/detail 拆分后端已经成型**（`/tree`、`/items` 本就不带
schema，描述 ≤500 字符；`/items/detail` 本就按需下发完整 manifest），
缺的是目录级失效信号与前端详情缓存。最小增量大法：

**后端（增量极小，全部挂现有汇聚点）**：

- 新增 `CatalogGenerationService`（AtomicLong 单调递增，进程内即可，
  不持久化——重启后前端会话缓存同样作废，语义自洽）。bump 挂五个
  汇聚点：`ToolRegistry.replaceExternal` / `unregisterExternal`
  （覆盖拓展热重扫与 MCP 上下线）、`SkillService` 保存/启停、
  Schedule CRUD、`ExtensionDirectoryRegistry.replaceRoot`
  （后三者绕过注册表，必须显式挂）。
- `GET /capability-admin/tree` 与 `/items` 响应各加 `generation` 字段；
  `AdminItem` 加 `manifestHash`（数据在 binding/Definition 上现成）。
- 新增探针 `GET /capability-admin/generation` → 只返回数字，
  供前端开房时廉价比对。
- **不引入** SSE 目录变更事件、etag 协商、分页——会话内 generation
  比对已覆盖诉求（克制，docs/36 "纯缓存不轮询"约束延续）。

**前端（只改 `capabilityCenterCache.ts` 一层 + CapabilityTreeView 接线）**：

- 缓存结构升级：`{ tree, treeGeneration, listings: Record<path,
  {generation, data}>, details: Record<path+manifestHash, detail> }`；
  详情从组件局部 state 提升进缓存——切目录、关开房都不再重拉。
- 开房流程：先探针比对 generation → 相同则整树渲染缓存（零等待）；
  不同则重拉 tree + 当前目录 listing，其余目录 listing 惰性失效。
- 手动全量刷新按钮（头部，与返回、搜索同排）：清全部缓存含 details +
  problems，重新拉取；按钮带一次 360° 旋转微动画（注意力锚定，
  符合视觉克制）。
- 变更操作（文件 op、skill 启停）后服务端 generation 已 bump，
  前端操作成功后直接重拉当前目录并更新缓存 generation，
  与既有 refreshAll 语义一致。
- `/api/v1/skills` 的 instructions 全文下发是管理面最重 payload，
  本轮记录不拆（技能量级小）；上量级后按同协议拆 detail，留痕 §4。

**容量目标**：千级能力条目下，开房首屏 = 1 次探针（命中缓存）或
1 次 tree + 1 次 listing（未命中），详情永远按需；整树 JSON 在千级
规模约百 KB 级，可接受，不提前优化。

## 3. 干净度配方沉淀（第二波正在执行的部分在此定标）

从应用壳原型与 chatgpt 照片提炼、已派给第二波的硬性规格：

- 字体：`14px/1.6` 基底、`-webkit-font-smoothing: antialiased`、
  强调字重 550-600 克制使用、组标题 11-12px + letter-spacing .12em；
  caption 最低可用字号 12px（中文 ≤11.5px 发虚）。
- 表面：hairline 用极淡色（`--hair` 系）、阴影两层（近距小 + 远距软）、
  卡片圆角 14px、行间分隔线左缩进对齐图标后（原型 `left:47px` 手法）。
- 颜色纪律：界面几乎无色——墨色阶 + 纸面；颜色只服务强调色与状态
  语义（小点 + 文字永远成对）。
- toast：深色胶囊、顶部居中、单次淡入（原型 `.toast` 同款）。

## 4. 不做（防反悔）

- 不做"发现间/货架/市场"（个人版阶段，docs/34 已裁决打包分发不做）；
  v12 的引导触点与情境推荐卡同样不做（无可推荐的货架）。
- 不做微光飞入/接线动画等叙事动效（视觉克制不变量）。
- 不做自定义嵌套分组文件夹（第一期）；不做回收站；不做能力级审批策略
  编辑（规则化权限是 docs/35 §5 独立排队项，届时再评入口）。
- 内核工具的移动/重命名永不做（包名即路径，第一原则）。
- 前端不引新依赖（ContextMenu 自绘；Radix 仅 dialog 现状保持）。
- 目录缓存不做 SSE 实时推送、不做 etag/分页、不做 localStorage 跨会话
  持久化（会话缓存 + generation 探针已够；重启后首拉一次是可接受成本）；
  `/api/v1/skills` 全量 payload 本轮不拆（上量级后按 §2.5 同协议拆，
  此条为留痕非承诺）。

## 5. 验收标准

1. 能力中心以居中覆盖大窗打开（`min(1120px,92vw) × min(760px,82vh)`，
   四周留出看得见的对话边缘；下层对话仅压暗不卸载），无位移/缩放/滑入
   转场（最多一次 opacity 淡入 ≤duration-fast）；点边缘空白 / Esc /
   "← 返回"三条路径等价返回，对话状态原位保留；
2. 文件真相对象可右键剪切/粘贴/重命名/删除，操作后热重扫即时反映；
   越界与内核对象被明确拒绝且提示人话；
3. 多选与拖放移动手感与资源管理器一致；冲突拒绝不覆盖；
4. 收藏区可钉选、可排序、重启保留；
5. 字号密度达到"比 chatgpt 设置页更大更清晰"（14px 基底、行规格对齐 §2.1）；
6. 索引缓存生效：开房命中缓存时零请求渲染（generation 探针相同）；
   未命中只拉 tree + 当前目录；详情按 path+manifestHash 缓存、切目录
   不重拉；手动全量刷新按钮清缓存重拉；热重扫/skill 启停后
   generation 变化可被探针感知；
7. 全部动画 ≤.5s 且为单次转场；无轮询；token 纪律零违规。
