## 1. 取舍原则（先于一切迁移点）

Iris 是个人 exe 形态的新形态 agent 探索线，不是服务千万台陌生机器的商业
CLI，也不是要推广交付的客户产品。这决定了迁移的过滤规则：

1. **学机制，不学平台成本**。参照系里为「跑在千万台陌生机器」付的生存
   成本（灰度开关、凭据泄漏防护、插件热装卸框架）一律不迁。
2. **五条不变量是硬过滤器**。与「发现优于塞满」「路径围栏」「历史不可丢」
   「审批常备」「视觉克制」冲突的做法，无论多好都不迁（如全机可读假设、
   把领域流程内嵌进常驻 prompt）。
3. **Iris 更强的架构不推倒**。后端权威历史、发现原语、审批管线是地基；
   迁移点只能加固地基，不能换地基。
4. **正确性优先于防御**（docs/40 裁决的延伸）。迁移来的每条机制先回答
   「为什么不会错」，重试与兜底是保险丝不是机制。

## 2. 体验 OKR 框架（结合 agent 特性）

Agent 产品与普通应用的本质差异：**系统在用户不在场时自主行动**。
所以体验 OKR 不围绕「点击率/留存」这类应用指标，而围绕四件事：
一次做对、过程可信、错了自愈、成本可见。

### O1 一次做对，失败可续（可靠性）

- KR1.1 失败分类可诊断率：run 失败记录的 failureCode 全部指向真实层
  （存储/provider/工具/用户取消），零「伪装分类」。数据源：run 表
  failure_code 列 + model_attempt_failure_detail。docs/40 已修存储侧，
  互猜审计确认的「未知工具名炸整轮」归入此 KR。
- KR1.2 断点继续成功率：失败 run 经 retry_same 恢复到完成的比率。
  数据源：run 状态迁移记录。
- KR1.3 静默卡死为零：任何组件故障最终都映射到可见状态（卡、失败、
  等待），不存在「永远 active」。审计确认的 SSE hub 静默丢事件即此类。

### O2 过程安静而可信（过程叙事）

- KR2.1 过程链人话化率：工具节点标题使用人话短语（现成 description）
  而非 snake_case 标识符的占比 → 100%。
- KR2.2 信任闭环：答案关键结论可一键溯源到产生它的过程节点
  （引用 chip → 节点定位 + 单次脉冲）。
- KR2.3 视觉噪音审计：常驻图标/常显控件逐项过「它减少了哪一次寻找」，
  无答案者改为 hover 现身或删除。

### O3 发现得到，错了自愈（工具层）

- KR3.1 参数错误一轮自愈率：工具参数失败返回「为什么错 + 下一步怎么做」
  的覆盖率 → 高频工具 100%；模型在同一轮内自我纠正而非多轮试探。
- KR3.2 截断零误判：所有列表型工具结果带截断信号，模型不再把
  「前 N 条」当全集。
- KR3.3 发现双通道覆盖：目录浏览（我知道去哪找）与关键词检索
  （我只知道要干什么）都可达全部工具。

### O4 成本透明可回归（效率）

- KR4.1 缓存命中率每轮可见：cache_read_tokens 已随 model_attempt 落库
  （OpenAiCompatibleStreamMapper 已抓 prompt_cache_hit_tokens），
  缺的是暴露与回归告警——命中率跌落即装配事故信号。
- KR4.2 重复内容零重发：同文件同区间重复读取返回 stub 而非全文。
- KR4.3 大结果零强塞：超阈值工具结果落盘存指针，模型收预览 + 按需取回，
  完整内容持久化不丢。

OKR 的用法：每个分期落地后对照 KR 打分；KR 全部写明数据源，
不接受无法度量的 KR。

## 3. 模型 effort 档位（真缺口，本期新设计）

**现状缺口**：`IrisModelProperties.Profile` 只有
kind/modelId/baseUrl/endpointPath/apiKey/timeoutSeconds/maxOutputTokens/
cumulativeToolArguments——没有任何推理强度概念。消费侧已能读
reasoning_content 与 reasoning_tokens（OpenAiCompatibleStreamMapper），
但请求侧从不设档：想换强度只能换整个 profile（连 base-url/key 一起换），
顶栏模型切换（914edaf）解决的是「换模型」不是「调强度」。

**设计**：

1. Profile 增加 `effort: low | medium | high`（默认 medium，
   缺省行为与今天一致）。装配请求时映射为 OpenAI-compatible 的
   `reasoning_effort` 字段；Anthropic kind 映射为其对应机制。
2. Provider 不支持该参数时：忽略并在启动目录登记 WARN（与 docs/41
   「能力缺失可诊断」一致），不静默降语义。
3. 运行时切换复用现有 model-profiles 通道：同一模型登记两个 profile
   （如 `deepseek` 与 `deepseek-deep`）即可今天就用上；后续的
   「同 profile 内切 effort」作为切换面增强，不重造通道。
4. **任务级自适应 effort 不做**（防过度工程）：由模型自己判断「这题要
   多想」听着美，但判错成本由用户付，且引入第二条决策链要审计。
   个人产品：用户一句话切档已经足够快。
5. effort 是请求标量：变更即 provider 前缀缓存分叉，必须纳入 §5.2 的
   请求 header 快照，否则缓存回归无法归因。

验收：配置 `effort: high` 的 profile 发出的请求体带对应参数；
不支持的 provider 启动 WARN 可见；顶栏切换后下一轮即生效（无需重启）。

## 4. 薄工具层十条（claude-code 迁移）

参照系核心思想：每个高频工具是「薄」的——一句话 description 供发现，
独立的行为合同供使用，错误信息本身就是教学。与 Iris「发现优于塞满」
完全同构，十条迁移点按分期排列。

### P0（小改动，直接收益）

1. **错误即教学**（O3-KR3.1）：参数失败的每个可预见分支返回
   「为什么错 + 下一步怎么做」的一句话人话，不是裸错误码。
   （参照：Edit 的 old_string 多处匹配 → 告知 replace_all 或加大上下文；
   路径不存在 → 附 cwd 说明 + Did-you-mean。）
   落地形态：写进工具开发规范 docs/03，高频工具先行。
2. **截断自报家门**（O3-KR3.2）：列表型工具（搜索/目录/清单）结果带
   appliedLimit/truncated 字段——**仅在真正截断时出现**——尾部附人话
   续页指引。成本极低，防的是模型把前 250 条当全集下错误结论。
3. **空结果归一化**：所有空工具结果在统一出口替换为非空人话
   （「未找到匹配文件」），防空 tool_result 引发模型轮次边界误判。
4. **结果排序即相关性**：搜索/列表结果按 mtime 降序（最近在动的排前面），
   截断保留头部 = 保留最相关；返回路径相对工作区以省 token。
5. **searchHint 关键词标签**（O3-KR3.3）：工具声明增加 searchHint
   （3-10 个与工具名正交的同义/领域词），搜索原语优先匹配。
   目录浏览覆盖「我知道去哪找」，searchHint 覆盖「我只知道要干什么」。

### P1（中改动，机制收益）

6. **description/prompt 双通道**：发现层恒为一句话（目录/搜索只看它）；
   完整行为合同（参数边界、默认上限、兄弟工具路由）独立存放，只在工具
   被选中后进入模型视野。发现层不被冗长规约拖垮。
7. **系统提示词工具路由表**：列举具体对照（读文件用 read_file 而不是
   shell cat）而非抽象原则，系统提示词与 shell 工具自身规约各放一份。
   防「有专用工具却走 shell」的旁路（旁路 = 绕过审批粒度、路径围栏、
   结果裁剪）。附并行调用规约：无依赖的调用同消息并行发出。
8. **读改写状态机**：per-session 记录 (path → 内容摘要/mtime)；
   编辑工具执行前校验「先读过且文件未被别人改过」，过期即拒绝并要求
   重读。审批管线管「要不要写」，这套状态机管「不基于过期视野写」——
   机制级正确性，不是兜底。
9. **重复读取 stub**（O4-KR4.2）：同文件同区间重复读取且文件未变时
   返回一行 stub（「内容未变，以对话中上次读取为准」），不重发全文。
   历史不丢，只是不重复注入。

### P2（大改动，量级收益）

10. **三层结果预算**（O4-KR4.3）：①工具自我设限（默认行数/条数上限）；
    ②单结果超阈值（参照系用 50k 字符）不截断而是**落盘存指针**，
    模型收预览 + 「完整内容已存至 X，需要时用 read_tool_result 取」；
    ③每轮聚合预算。Iris 的后端权威历史 + tool_output_payload 表正好
    承载②——这是「发现优于塞满」在结果侧的镜像。先做②，①③随工具
    规范逐步铺。

**明确不学**：Bash prompt 内嵌整套 git/PR 流程（违反发现优于塞满）；
全机可读假设（冲突路径围栏）；「永不新建文件/文档」的编码助手规范
（个人助手帮用户写文档是正常需求）；商业 CLI 的平台化防御层；
工具定义内嵌 UI 渲染（Iris 走前端组件）。

## 5. 上下文缓存与装配纪律（deepseek-harness 迁移）

参照系核心不变式：**模型可见 ⟺ 已持久**——每个到达模型的请求都能从
仅追加的日志逐字节重建，前缀缓存稳定性是这条不变式的涌现推论。
Iris 已有后端权威历史，迁移的是缓存纪律，不是 Cordis 插件框架。

### 5.1 压缩摘要请求复用已预热前缀（最高价值单条）

参照系实测：自动压缩恰好在最后一次请求预热 provider KV Cache 之后
触发，若摘要请求用独立 system prompt + 拍平文本，第一个 token 就分叉，
对话最大时付双倍提示词成本。改法：摘要请求逐字复现最后一个已路由
请求的前缀（system + 可见工具 schema + 历史），摘要指令挪到**尾部
user 消息**。缓存复用是尽力而为，正确性不受影响。
落地前先验证 Iris 当前摘要请求的装配形态（AutoCompactionService/
CompactionLauncher），确认分叉点后改造。

### 5.2 请求 header 完整快照持久化

每个请求的非历史状态（渲染后 system 版本、可见工具集、调用配置、
**effort 档位**）写成完整快照事件落库（完整快照而非 delta——参照系
明确否决 header-delta 编解码器）。每请求一条小事件，换来缓存漂移
可归因、回放分歧可审计。与「历史不可丢」一致：只增不改。

### 5.3 缓存命中率成为生产信号（O4-KR4.1）

Iris 已把 cache_read/cache_miss tokens 随 model_attempt 落库（数据源
现成），缺的是：逐步骤暴露（前端 context-usage 或日志）、以及
「header 快照变更/压缩后命中率跌落」的回归判读。配套 5.2 形成闭环：
装配变动 → 快照事件 → 命中率变化可归因。

### 5.4 统一装配点

「本次哪些工具 schema 可见」与「提示词文本」收敛为一个装配值对象 +
一个拦截点。Iris 的发现原语不推倒——可见性过滤只是装配重写的一种，
避免将来「按域聚焦/压缩后收窄」要同时改两个服务。

### 5.5 能力目录的消息生命周期

能力目录若进模型视野，采用：digest 判重（只对 name+description 对取
摘要）→ 变更发完整替换（不做 diff 语义）→ 清空发空信封墓碑 →
压缩遮蔽后自动重建 → 快照不完整时保留旧视图不发布半成品。

**明确不学**：Cordis 运行时插件框架（Spring DI 已够）；header-delta
自定义编解码；按请求/按轮重算的上下文槽位（每步重组既漂移又毁缓存，
会话中途变化一律走仅追加历史）；有状态 LLM 客户端当第二真相
（Iris 日志唯一真源已是对的）。

## 6. 前端安静打磨（WonWork 蓝图迁移）

参照系手法总结：**正常即安静**——ok 零标记、off 用透明度不用颜色、
只有 err 动用警告色；反馈三级（轻操作无声 / 实质操作就地反馈 + 可撤销 /
不可逆才打断且必带人话后果）；不靠颜色靠层次（字重三档、灰阶四级、
mono 承载数字与路径）；动画单次、≤450ms、只用于注意力锚定。

### P0（一行到一天）

1. **节点标题两段式**（O2-KR2.1）：faint 类别小前缀（从 capabilityPath
   末段派生）+ 550 字重人话短语（用现成 description），替换裸
   snake_case toolName。过程链从「日志」变「叙事」，零新数据源。
2. **沉淀摘要行人话化 + token 可见**：动词短语聚合 + 耗时 + tok 成本
   （「思考 · 调用 12 次 · 22 秒 · 25.7k tok」），去掉常驻彩色状态图标。
   措辞迁移与既有「结算自动全展开」裁决不冲突。
3. **展开 chevron hover 才现身**：收合态每行少一个常驻 glyph，
   「可展开」成为发现而非噪音。
4. **子代理胶囊完成态逗留 1.6s**：完成不瞬消——变静止完成态原地停留
   再淡出。最低成本的完成确认，符合注意力锚定。
5. **角标 2.5px 底色描边罩**：能力砖角标从图标上浮出而非贴边叠色，
   暗色主题下尤其明显。
6. **MoveToPopover 标注并禁用当前落点**：「现在在这」弱标记不可点，
   把必然失败的操作在渲染层消灭——补 docs/39 已知遗留（当前靠后端
   错误 toast 兜底）。
7. **空态文案给下一步**：空态 = 一句话现状 + 一条可执行的下一步，
   顺带教心智模型（「它一定住在某个目录里」教「每个能力有且只有一个
   家」）。沿用自然短句风格，不用间隔号拼接腔。

### P1（机制小改）

8. **思考节点沉淀自动收起**：thinking 节点 settled 后若用户未手动展开
   过则自动收起，标题回填耗时；用户手动展开优先权保留（与
   seedExpandedRound 一次性播种语义一致）。思考内容只在当下有阅读
   价值，沉淀后是链条最大噪音源。

### P2（信任闭环，需后端配合）

9. **答案引用 chip 逆流溯源**（O2-KR2.2）：答案关键结论后内联引用
   chip，点击时过程链若已收拢先展开 → 目标节点平滑滚动居中 → 单次
   脉冲 1.3s。Iris 现有 useAnswerQuote 是答案→输入框（方向相反），
   溯源是答案→过程。后端权威历史有全部节点，需建立答案段 ↔
   工具/子任务节点的引用映射（可先按子 Run 粒度启发式）。

### 用户裁决项（不擅自改）

- **结算后过程链形态**：蓝图「沉淀 1.8s 自动收拢成一行摘要」 vs
  Iris 已落地的「结算自动全展开」（f0b4f62 裁决）。两边各有理——
  蓝图要历史轮次安静不占垂直空间，Iris 要完成瞬间可检视。
  本稿只迁措辞与 token 可见，收拢时序交用户体验后裁决。

**明确不学**：强制滚底（Iris 智能跟随 + 离底「回到最新」已更强）；
假流式打字机（SSE 增量 + useReveal 是正道）；流式光标（已删不回引）；
过程面窄列底（与已裁决的「过程链与正文同平面」冲突）；大面积成功绿
当进度条（primary/15 淡染已等价且不依赖色觉）；触顶热区/右缘芽等
花哨移动。

## 7. 轨道 DAG：定位裁决与分期（v18 收敛）

**核心裁决：轨道 = 对齐物 + 投影，不是执行引擎。** 跑事情的永远是
agent 自己与 Pipeline（docs/28 已定首版不做任意 DAG）；轨道只回答
三件事——这条链有哪些关键节点、每步靠什么回执信号算走完、什么条件
走哪条边。这条分界线写死，后续所有工作才不会滑向图调度器。

参照系与 Iris 的同构点令人安心：「JSON 文档是真相、图是派生投影、
源文档可编辑、不合法保持旧投影」正是 Iris「SQLite 是真相、投影派生」
的哲学。

分期：

- **P0｜Skill 步骤补 done_when**：Skill 正文约定增加可选 done_when
  ——一句话走完标志，绑定工具回执/产物在场（「回执 PUBLISHED」
  「plan_id 在场」），不写自我感觉。零执行改动、零前端改动，
  为将来一切点亮/投影/沉淀打下「诚实信号」地基。与既有 verify/
  commit gate 哲学一致。
- **P1｜轨道文档作为能力树叶子**：带 when_to_use 的轨道文档走
  list_capabilities/read_capability 发现原语按需加载，不进系统提示词；
  SQLite 单表（id/version/source/nodes/edges/when_to_use），不引中间件；
  没有匹配轨道就自由走，不阻塞。
- **P1｜诚实信号点亮 + 对话内迷你进度条**：节点状态只从持久化回执
  推导（ToolObservation 落盘时已掌握），通用 read/grep 调用不挪光标，
  模型自报不算数；前端是一排点的迷你轨（done/当前呼吸/未走）+
  「3/9 · 轨道 ›」入口，复用现有胶囊条模式，不需要 SVG 布局引擎。
  全图收在检查器里按需打开，是体验数据证明需要之后再做的事。
- **P2｜沉淀流**：无轨道任务走通后安静邀请「沉淀为轨道吗」——抽取
  关键节点、剥离具体参数泛化、校验工具存在与图连通，存 v0.1.0 进
  轨道库。沉淀物而非设计物：「第三次做同类事」才是沉淀信号，
  避免为没重复过的流程造死图。
- **P3｜示意化地铁图布局**（只在全图检查器立项时）：脊柱 = 最长链
  定栏、回边走左走廊、支线挂右袋、出口虚线桩。直接用参照系已验证
  的布局规则，**不引入 dagre/ELK**（通用布局会让近线性主链蛇形漂移，
  已被实测否定）。

**五个陷阱（写死防反悔）**：
1. 把轨道做成执行引擎（变成第二个 Pipeline，重发明调度/恢复/失败语义）；
2. 图先行——为没重复过的流程设计轨道（死图与配置债）；
3. 通用布局内核/拖拽画布（5 个节点造图编辑器是教科书级过度工程）；
4. 通用工具调用也进图、按模型自报点亮（谎言管道；过程面已承担
   时间线角色）；
5. 把 DAG 当多代理/定时/流水线的解（durable child Run + mailbox、
   cron 叶子、顺序 Pipeline 已各就各位，不需要图）。

## 8. 不做总清单（跨参照系汇总）

- 不做插件热装卸框架、灰度开关平台、凭据泄漏防护层（商业 CLI 生存
  成本，个人 exe 不需要）；
- 不做 header-delta、按轮重组上下文槽位、有状态 LLM 客户端第二真相；
- 不做任务级自适应 effort（用户切档已够快，判错成本用户付）；
- 不做假流式、强制滚底、流式光标、大面积状态色；
- 不做 DAG 执行引擎、图形化编排 DSL、通用图布局依赖、工作流市场；
- 不把领域流程（git/PR 协议）内嵌进常驻 prompt——做成可按需加载的
  技能/文档。

## 9. 验收标准（按分期）

**P0 完成时**：
1. 高频工具的参数失败返回人话下一步（抽查 read/edit/search/shell 类
   各一）；
2. 列表型工具结果带截断信号且仅截断时出现；
3. 空结果全部非空人话；搜索结果 mtime 降序；
4. Skill 正文约定含 done_when 写法，docs/03 同步；
5. 过程链节点标题两段式上线；摘要行带 tok；chevron hover 现身；
   胶囊完成逗留；角标罩；here 落点禁用；空态文案。

**P1 完成时**：
6. Profile 支持 effort 档并映射到请求参数，不支持则 WARN 可诊断；
7. 摘要请求逐字复用已预热前缀（cache_read_tokens 在压缩轮不跌落）；
8. 请求 header 快照落库，含 effort；命中率逐步骤可见；
9. 读改写状态机拦截过期视野写（有测试）；重复读取返回 stub；
10. 轨道叶子可发现可读取；done_when 回执点亮迷你进度条。

**P2 完成时**：
11. 大结果落盘指针 + read_tool_result 取回全链路；
12. 答案引用 chip 溯源到过程节点；
13. 沉淀流在「同类任务第三次」场景产出可审阅的轨道草稿。

## 10. P0 落地发现的后续缺口（登记于 2026-08-27）

1. **工具节点投影缺 description**：节点标题两段式目前用 summary 首行
   （偏结果陈述），真正的人话动作短语需后端把工具 description 随
   ToolNode 投影——归入 P1 与「双通道文案」合流。
2. **round 维度无 token 投影**：摘要行 tok 可见需要 round 级 token 数
   （model_attempt 已落库，数据源现成）——归入 P1「缓存命中信号
   暴露」一起做。
3. **能力 availability 未拆分 off/warn**：能力砖目前 warn 黄点与停用
   共用一枚，蓝图「off 用透明度空心点」无渲染源——随能力房下一
   迭代拆分语义后补。
4. **MoveToPopover 不落根**：住在根目录直下的能力当前落点不显示
   「现在在这」（根不在落点列表）——「移到根」是否支持留待裁决。
5. **list/search 全量扫描成本**：mtime 排序要求先收集候选再排序，
   不再命中即停（受 1 万条目扫描预算约束）——大目录树下实测一次，
   成为瓶颈再优化。
